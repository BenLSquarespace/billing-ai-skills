# billing-ai-skills

A collection of AI skill frameworks for the Billing team, providing consistent guidelines for common engineering tasks.

## Quick Start

Reference skill files when asking AI to help with tasks:

```
"Using @ai-skills/pr-reviewer/SKILL.md, review this PR..."
"Follow @ai-skills/pr-reviewer/SKILL.md to review PR #1234 in billing-invoice-service"
```

### Example Prompts

**Review a specific PR:**
```
Using @ai-skills/pr-reviewer/SKILL.md, review PR #567 in sqsp/billing-invoice-service.
Focus on database migration safety and version management.
```

**Review a PR diff you've already pulled up:**
```
Using the guidelines in @ai-skills/pr-reviewer/SKILL.md, review the changes in this diff.
```

**Review across repos for a multi-repo change:**
```
Using @ai-skills/pr-reviewer/SKILL.md, review these related PRs:
- sqsp/billing-invoice-service #567
- sqsp/v6-billing-facade #89
- sqsp/squarespace-v6 #43210
Check cross-repo version coordination and deployment order.
```

## Prerequisites

- **GitHub CLI (`gh`)** authenticated with access to the `sqsp` organization
- **Cursor / AI IDE** that supports `@`-referencing files

## How the PR Reviewer Skill Was Built

The PR reviewer skill was generated by analyzing ~13,000 lines of actual PR review comments from 15 billing team members across three repositories over 12 months (March 2025 – March 2026). The analysis covered:

- `sqsp/billing-invoice-service` (Ripley)
- `sqsp/v6-billing-facade`
- `sqsp/squarespace-v6`

Comments were collected using the GitHub CLI, summarized per-repo, and then distilled into the checklist and guidelines in the skill file. This ensures the skill reflects real team standards rather than generic best practices.

## Adding New Skills

To add a new skill:

1. Create a new folder under `ai-skills/` with a descriptive name (e.g., `incident-response/`)
2. Add a `SKILL.md` file with the main documentation
3. Include any supporting files in the same folder (templates, examples, scripts)
4. Update this README with the new skill in the table above

Each `SKILL.md` should include:

1. **Purpose** — What types of questions/tasks this skill covers
2. **Prerequisites** — What access/credentials are needed
3. **Process** — Step-by-step approach to follow
4. **Checklist** — Validation criteria or things to verify
5. **Output Format** — How findings should be presented
